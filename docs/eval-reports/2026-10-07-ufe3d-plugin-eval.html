You set this up in two places: on each move link, and once globally in the Advanced settings.

## 1. Per link: let the follow-up be queued early

Open the move in the Move Editor and go to **Link Moves → Move Links**. Each move link entry has these settings:

- **Frame Links**: the range of active frames where the cancel into the next move can happen.
- **Link Conditions**: whether the link needs a hit confirm, a counter move, or no extra condition.
- **Input Buffer Type**: choose no buffer, the global buffer, or a custom buffer for this link.
- **Buffer Time (frames)**: the size of the custom buffer window. It only applies when Input Buffer Type is Custom.
- **Startup Frame**: where the linked move starts in its own startup timeline.
- **Linked Moves**: the list of moves this link can go into.

Each entry under **Linked Moves** has its own **Input Buffer Type** and **Buffer Time (frames)**, with the same three choices. It also has **Ignore Inputs (Auto Execution)**, **Ignore Character States**, **Ignore Meter Requirements**, **Allow Block Cancel**, **Startup Frame**, **Character Specific** / **Character Name**, and **Move**.

The manual describes these three Input Buffer Type choices but doesn't list their exact enum names. Check the dropdown in your editor for the labels.

## 2. Global buffer window

Go to **Global Editor → Advanced**. The manual calls this the place where UFE's global buffer window is configured:

- **Execution Buffer Type**: the global buffer behavior. The options are:
  - `OnlyMoveLinks`: buffering only works when chaining through move links.
  - `AnyMove`: inputs can be buffered into any move.
  - `NoBuffer`: no input buffering.
- **Execution Buffer (frames)**: the size of the global window. Bigger values let players input the next move earlier.
- **Plinking Delay (frames)**: a separate timing window that decides input priority when buttons are pressed close together. It's not the buffer.

## Typical setup for combos

1. Under Global → Advanced, set **Execution Buffer Type** to `OnlyMoveLinks` (or `AnyMove` if you want buffering everywhere). Set **Execution Buffer (frames)** to something like 3–8.
2. On each move link, set **Input Buffer Type** to the global option. Switch it to Custom with its own **Buffer Time (frames)** only for links that need a tighter or looser window.
3. Set **Frame Links** to the frames where the cancel should actually fire. A buffered input waits and then runs once that window opens.

The 3–8 frame range and the description of how a buffered input waits are my own reading. The manual doesn't state them.
